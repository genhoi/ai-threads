# Нить

[English](README.md) · **Русский**

«Нить» — локальное веб-приложение, которое помогает найти и продолжить сессию агента для
программирования. Оно собирает журналы Claude Code, Codex, Grok, Kimi, ZCode и Cursor Agent в один
список, ищет по названиям и переписке и даёт команду, которая продолжит сессию в терминале. По кнопке
агент составляет сводку по одной сессии или по всем сессиям за 3–5 дней.

Интерфейс на русском и английском. «Нить» берёт язык браузера, а если он ни русский, ни английский —
английский. Закрепить язык можно [настройкой](#настройки) `language`.

## Что умеет

- Один список сессий всех агентов: проект, ветка, время, последний ответ агента. Сессию можно
  переименовать, закрепить наверху, отметить завершённой или скрыть из списка.
- Быстрый поиск по названию, ветке, пути, ID и сводке. Переключатель «+ переписка» добавляет поиск
  по тексту переписки, в последних 512 КБ каждого журнала.
- Полный поиск без агента: напишите запрос и выберите под полем «Искать в журналах целиком» или
  нажмите Enter, если обычный поиск ничего не нашёл. «Нить» читает журналы целиком, вместе с выводом
  команд и прочитанными файлами, и показывает фрагмент вокруг каждого совпадения. Это несколько секунд,
  ход поиска виден.
- Умный поиск обычной фразой: напишите запрос и выберите под полем «Спросить агента» или нажмите
  Ctrl+Enter, например «найди сессии по переходу на партиции message_profile в claude code и
  codex». Агент разбирает запрос на слова для поиска и фильтры по агенту, проекту и дате. «Нить» ищет
  эти слова в журналах, а агент отбирает подходящие сессии и пишет к каждой, чем она отвечает
  запросу. Запрос из одного слова, например номер задачи, ищется сразу, без разбора агентом. Обычно
  поиск занимает 1–3 минуты; сессии, найденные по словам, видны ещё до того, как агент закончит.
- Работа агента открывается справа, как сессия: что «Нить» отправила агенту, как он рассуждает (если
  CLI это отдаёт), какие файлы читает, какие команды запускает и что отвечает — в реальном времени.
  Когда он закончит, ему можно написать в той же сессии — прямо на странице или в терминале. Такой же
  журнал есть у сводок.
- Выбор агента, модели и уровня рассуждений у кнопок «Спросить агента» и «Составить». По умолчанию —
  как настроено в самом CLI, а список моделей «Нить» берёт у CLI, поэтому новые модели появляются без
  правки настроек «Нити».
- Готовая команда продолжения, например `cd -- <папка> && codex resume <id>`. Галочка в настройках
  добавляет к ней флаг агента для работы без запросов подтверждения.
- Скрипт, который восстанавливает несколько сессий сразу: вкладки Windows Terminal (в WSL), окна tmux
  или список команд. Вкладки Windows Terminal берут папку и команду у «Нити», поэтому она должна быть
  запущена, когда вы запускаете скрипт.
- Статус запущенных сессий. У Claude Code «Нить» показывает, работает агент или ждёт вашего ответа,
  а в шапке есть счётчик сессий, которые ждут вас. У Grok видно только, что сессия запущена.
  Остальные агенты статус не сообщают.
- Сводка по сессии: короткое название, что сделано, следующий шаг и до трёх связанных сессий. Экран
  «Сводка» подводит итоги за 3, 4 или 5 дней по проектам и перечисляет, что осталось сделать. Сводки
  пишет установленный CLI: Kimi, Claude Code, Codex или Grok.
- Автоматические запуски (`codex exec`, `claude -p`, `grok -p`, `kimi -p`) не попадают в «Мои», они
  есть только во «Всех». Обычно их запускают другие агенты для ревью и сводок, а также сама «Нить»
  для своих сводок и умного поиска.

## Запуск

Нужен Python 3.10 или новее. Сторонних пакетов приложению не нужно. Для сводок и умного поиска нужен
ещё один из CLI: Kimi, Claude Code, Codex или Grok.

```bash
git clone https://github.com/genhoi/ai-threads.git
cd ai-threads
python3 -m ai_threads            # порт меняется ключом --port
```

Откройте в браузере http://127.0.0.1:8765. При первом запуске «Нить» читает все журналы, список
заполняется по ходу чтения.

Приложение проверено в Linux и в WSL 2. В Windows его нужно запускать внутри WSL.

## Какие агенты поддерживаются

«Нить» показывает сессии каждого агента, у которого есть папка с сессиями. Чтобы продолжить сессию
или написать сводку, нужна ещё программа агента; её «Нить» ищет в `PATH`. Если папка или программа
лежат в другом месте, путь можно указать в настройках.

| Агент | ID | Папка с сессиями | Команда продолжения | Флаг для `skip_approvals` | Пишет сводки |
|---|---|---|---|---|---|
| Codex | `codex` | `~/.codex` (`CODEX_HOME`) | `codex resume {id}` | `--dangerously-bypass-approvals-and-sandbox` | да |
| Claude Code | `claude` | `~/.claude` (`CLAUDE_HOME`) | `claude --resume {id}` | `--dangerously-skip-permissions` | да |
| Grok | `grok` | `~/.grok` (`GROK_HOME`) | `grok --resume {id}` | `--always-approve` | да |
| Kimi | `kimi` | `~/.kimi-code` (`KIMI_CODE_HOME`) | `kimi --session {id}` | `--auto` | да |
| ZCode | `zcode` | `~/.zcode` (`ZCODE_HOME`) | нет: сессию продолжают в приложении ZCode | — | нет |
| Cursor Agent | `cursor` | `~/.cursor` (`CURSOR_HOME`) | `cursor-agent --resume {id}` | `--force` | нет |

Сводку можно составить по сессии любого агента, в том числе ZCode и Cursor Agent. Последний столбец
показывает, какие агенты умеют сами писать сводки.

Файлы агентов «Нить» только читает. Одно исключение: когда «Нить» читает базы SQLite у ZCode и Cursor
Agent в режиме WAL, сам SQLite может обновить служебный файл `-shm` рядом с базой. Данные при этом не
меняются.

## Настройки

Настройки меняются на экране «Настройки» (шестерёнка в шапке) или в файле
`~/.config/ai-threads/settings.json`. Папка учитывает `XDG_CONFIG_HOME`, а `AI_THREADS_CONFIG` задаёт
полный путь к файлу. В файле достаточно указать то, что отличается от умолчаний. Например,
продолжать сессии Codex без запросов подтверждения, составлять сводки по сессиям через Claude Code и
всегда показывать интерфейс на английском:

```json
{
  "agents": {
    "codex": {"skip_approvals": true}
  },
  "summary": {"agent": "claude"},
  "language": "en"
}
```

В названиях полей `<id>` — ID агента из таблицы выше.

| Поле | По умолчанию | Что задаёт |
|---|---|---|
| `agents.<id>.enabled` | `true` | показывать ли сессии агента |
| `agents.<id>.home` | см. таблицу агентов | папка с сессиями; переменная окружения важнее |
| `agents.<id>.program` | найденная в `PATH` | путь к программе агента |
| `agents.<id>.skip_approvals` | `false` | добавить к команде продолжения флаг агента для работы без запросов подтверждения (см. таблицу агентов) |
| `open_with` | `auto` | формат скрипта восстановления по умолчанию: `wt`, `tmux` или `plain`. `auto` — Windows Terminal в WSL, иначе tmux, если он установлен, иначе список команд |
| `tmux_session` | `nit` | имя tmux-сессии в скрипте восстановления |
| `summary.agent`, `digest.agent` | `auto` | кто составляет сводки по сессии и сводки за несколько дней: `kimi`, `claude`, `codex`, `grok`. `auto` — первый установленный в этом порядке |
| `search.agent` | `auto` | кто разбирает запрос умного поиска и отбирает сессии; значения те же |
| `summary.timeout`, `digest.timeout`, `search.timeout` | `300`, `900`, `300` | сколько секунд ждать ответа агента, от 10 до 7200 |
| `language` | `auto` | язык интерфейса и сводок: `ru` или `en`. `auto` — как в браузере, а если там ни русского, ни английского — английский |
| `temp_dirs` | `["/tmp", "/var/tmp", "~/.local"]` | сессии из этих папок и вложенных в них считаются временными и не попадают в «Мои» |

`open_with` и `tmux_session` есть только в файле, на экране настроек их нет. Переменные окружения
важнее файла: это переменные папок из таблицы агентов и `AI_THREADS_SUMMARY_TIMEOUT`,
`AI_THREADS_DIGEST_TIMEOUT`, `AI_THREADS_SEARCH_TIMEOUT` для времени ожидания в секундах.

Файл читается заново при каждом изменении, перезапускать сервер не нужно. Если в файле ошибка,
например сломанный JSON, неизвестное поле или неверное значение, приложение работает с умолчаниями
и показывает причину при запуске и на экране настроек.

## Данные и приватность

- Ваши названия, закрепления, отметки, сводки по сессиям и сводки за несколько дней хранятся в
  `~/.local/share/ai-threads/state.json`. Папку меняет `AI_THREADS_DATA`. Там же лежит `cache.json`,
  кеш разбора журналов; его можно удалить.
- Меню «Данные» в шапке выгружает ваши названия, закрепления, отметки и сводки по сессиям в один
  JSON-файл и загружает их обратно. Загрузка добавляет данные к текущим и ничего не удаляет, но у
  сессии, которая уже есть, заменяет название и сводку на те, что в файле. Сводки за несколько дней
  в выгрузку не входят: их можно составить заново.
- Сводки и умный поиск запускают выбранный CLI, и он отправляет данные своему поставщику модели, как
  при обычной работе с этим агентом.
- Для сводки по сессии CLI читает журнал сессии вместе с выводом команд и прочитанными файлами. У ZCode
  и Cursor Agent «Нить» передаёт только текст переписки. Ещё CLI получает названия до 30 других сессий
  из той же папки за последние 30 дней, кроме автоматических, временных и скрытых, чтобы найти
  связанные.
- Для сводки за несколько дней CLI получает названия, готовые сводки и короткие выдержки сессий за
  период и может открыть часть журналов целиком.
- Для умного поиска CLI получает запрос, названия проектов из текущего раздела («Мои» или «Все») и по
  каждому из 30 лучших кандидатов: название, сводку, первый запрос и до трёх фрагментов переписки.
  Вывод команд и прочитанные файлы не отправляются, даже если слова нашлись там.
- Без нажатия «Составить» или «Спросить агента» журналы никуда не уходят.
- Рабочие папки этих запусков хранятся неделю в `~/.local/share/ai-threads/runs`: Claude Code и Kimi
  находят сессию по папке, и без неё агенту нельзя было бы написать потом.
- CLI запускается без права менять файлы: Kimi и Claude Code получают только инструмент `Read`, Codex
  и Grok работают в песочнице только для чтения.

## Безопасность

Сервер слушает только `127.0.0.1` и не спрашивает пароль: открыть его может любой пользователь или
программа на этом компьютере. Запросы с чужим заголовком `Host` отклоняются. Запросы, которые что-то
меняют, принимаются только с заголовком `Origin` самой «Нити», поэтому сторонний сайт в браузере не
может их отправить. Браузер передаёт серверу только ключ сессии; путь к журналу сервер находит сам.

## Разработка

```bash
./scripts/setup.sh                      # pytest и Playwright с Chromium и WebKit в .venv
.venv/bin/python -m pytest -q           # все тесты; без браузера: --ignore=tests/ui
.venv/bin/python scripts/demo_screenshots.py   # снимки для README на выдуманных сессиях
```

Для WebKit в WSL нужны системные библиотеки: `sudo .venv/bin/python -m playwright install-deps webkit`.
Тесты работают с копиями фикстур из `tests/fixtures` и заглушками CLI из `tests/stubs`, настоящие
журналы и данные не трогают. Как устроено приложение и как подключить нового агента — в
[docs/architecture.md](docs/architecture.md).
