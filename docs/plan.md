# «Нить» 2: устройство

Интерфейс — `design/v2/untitled/project/Screens.dc.html` и компоненты рядом с ним (папка `design/`
не в git, это выгрузка из Claude Design). Сценарии — [concept.md](concept.md), доступ с телефона —
[phone-access.md](phone-access.md). Первая версия на Python лежит в ветке `v1`.

## Части

Один бинарник `nit` на Go. Интерфейс на TypeScript и Preact собирается esbuild в `web/dist` и вшивается
в бинарник (`web/embed.go`). Как устроен интерфейс — [web/README.md](../web/README.md).

| Пакет | Что делает |
|---|---|
| `cmd/nit` | запуск: флаги, порт, папка данных, сигналы |
| `internal/model` | общие типы: сессия, состояние, сообщение |
| `internal/agents` | по файлу на агента: где журналы, как их читать, как запустить и продолжить, какие модели, реестры живых сессий |
| `internal/catalog` | собирает сессии всех агентов, кэширует разбор в `catalog.json`, следит за новыми журналами |
| `internal/store` | пометки человека: названия, закрепления, скрытые, завершённые, просмотренные, сводки, настройки проектов |
| `internal/settings` | `settings.json`, совместим с первой версией |
| `internal/tmux` | свой сокет `ai-threads`: открыть, закрыть, список, `capture-pane`, `send-keys`, подключение через pty |
| `internal/terminal` | WebSocket между xterm.js и tmux |
| `internal/launch` | терминал новой сессии, копии репозитория (git worktree), подбор ветки, проверки перед удалением копии |
| `internal/live` | состояние сессий в терминалах «Нити» по экрану и отметка «новое» |
| `internal/summary` | сводка по сессии и за несколько дней: запускает агента без интерфейса |
| `internal/remote` | доступ с телефона: узел Tailscale внутри процесса (tsnet), вход по ключу, устройства |
| `internal/server` | HTTP API, поток событий, поиск, запуск и продолжение сессий, раздача интерфейса, проверка Host и Origin |

## Агенты

| Агент | Запуск и продолжение | Пишет сводки | Реестр живых сессий |
|---|---|---|---|
| Claude Code | да | да | да: работает или ждёт, в терминале или в фоне |
| Codex | да | да | нет |
| Grok | да | да | только «процесс жив» |
| Kimi | да | да | нет |
| Cursor Agent | да | нет | нет |
| ZCode | нет: сессии только читаются из его базы | нет | нет |

Claude Code и Grok получают ID новой сессии флагом при запуске. У остальных «Нить» находит новую
сессию по журналам: самую раннюю сессию этого агента в той же папке, созданную после запуска. Kimi получает первый
запрос текстом в терминал после старта, остальные — аргументом командной строки.

## Данные

Пути первой версии сохранены, поэтому вторая подхватила всё накопленное.

Настройки — `$AI_THREADS_CONFIG` или `$XDG_CONFIG_HOME/ai-threads/settings.json`
(по умолчанию `~/.config/ai-threads/settings.json`). Папка данных — `$AI_THREADS_DATA` или
`$XDG_DATA_HOME/ai-threads/` (по умолчанию `~/.local/share/ai-threads/`). В ней:
- `state.json` — пометки человека, сводки, настройки проектов, открытые терминалы и копии;
- `catalog.json` — кэш разобранных журналов;
- `terminals.json` — последние состояния терминалов для экрана после перезагрузки;
- `remote.json` — ключ входа с телефона и хэши ключей устройств, права 0600;
- `runs/` — рабочие папки сводок.

Ключ сессии, как в первой версии: `<агент>:<id>`, например `claude:77be55f8-…`. По нему хранятся
пометки человека, поэтому формат не меняется.

Копии репозитория: `~/.nit/worktrees/<проект>/<ветка>`. Имя сессии tmux задаётся шаблоном
в настройках, по умолчанию `nit-{project}-{branch}`. Состояние узла Tailscale — в `~/.threadgate`.

## Настройки и переменные окружения

Все настройки меняются на экране «Настройки». В `settings.json` они лежат так:

| Поле | Что значит | По умолчанию |
|---|---|---|
| `agents.<агент>` | `enabled` — показывать в списке, `home` — папка с журналами, `program` — путь к программе, `flags` — флаги запуска, `skip_approvals` — запускать без подтверждений | включены, папки и программы ищутся сами |
| `summary`, `digest` | кто пишет сводку по сессии и за несколько дней (`agent`: `auto` или агент) и сколько минут ждать (`minutes`) | `auto`, 5 и 15 минут |
| `language` | язык сообщений сервера и сводок: `auto`, `ru`, `en` | `auto` |
| `service` | признаки служебной сессии: `auto_commands` — команды запуска без человека, `temp_dirs` — временные папки | `codex exec`, `claude -p`, `grok -p`, `kimi -p`; `/tmp`, `/var/tmp`, `~/.local` |
| `tmux.session_name` | шаблон имени сессии tmux: `{project}`, `{branch}`, `{agent}`, `{id}` | `nit-{project}-{branch}` |
| `remote` | доступ с телефона: `enabled`, `funnel` — адрес открыт и из интернета, `hostname` — имя узла, `state_dir` — папка состояния узла | выключен, `nit`, `~/.threadgate` |

«Авто» для сводок берёт первого установленного из Kimi, Claude Code, Codex, Grok.

Флаг `-port` меняет порт (по умолчанию 8765). «Нить» слушает только 127.0.0.1. Флаг
`-import-gate-token <файл>` (или переменная `NIT_IMPORT_GATE_TOKEN`) переносит ключ входа
с телефона из отдельного шлюза, которым доступ был устроен до второй версии.

| Переменная | Что меняет |
|---|---|
| `AI_THREADS_CONFIG`, `AI_THREADS_DATA` | путь к настройкам и папке данных |
| `AI_THREADS_TMUX_SOCKET` | путь к сокету tmux вместо `ai-threads`; на нём тесты держат свои терминалы |
| `AI_THREADS_SUMMARY_TIMEOUT`, `AI_THREADS_DIGEST_TIMEOUT` | сколько секунд ждать сводку; важнее настроек |
| `CLAUDE_HOME`, `CODEX_HOME`, `GROK_HOME`, `KIMI_CODE_HOME`, `CURSOR_HOME`, `ZCODE_HOME` | папки агентов, если в настройках не задано другое |
| `SHELL` | оболочка, через которую запускается агент (`$SHELL -ic`): так подхватываются PATH и псевдонимы из `.bashrc` |
| `NIT_REMOTE_DEBUG=1` | подробный журнал узла Tailscale |

## Состояния сессии

| Состояние | Когда | Знак |
|---|---|---|
| `starting` | терминал открыт, агент ещё ничего не вывел | пунктирное кольцо |
| `working` | агент выполняет задачу | кольцо |
| `waiting` | агент закончил ход или спрашивает разрешение | круг, у новой ещё ореол и плашка «новое» |
| `error` | процесс агента вышел с ненулевым кодом | ромб и код |
| `exited` | процесс вышел без ошибки, терминал ещё открыт | галочка |
| `idle` | терминала нет, сессию можно продолжить («в истории») | без знака |

«Завершена» — пометка человека, а не состояние процесса.

Откуда берётся состояние. Claude Code сам пишет в свой реестр, работает он или ждёт, и «Нить» берёт
состояние оттуда (`internal/agents/live.go`). Для остальных агентов, запущенных в «Нити», раз в секунду
снимается экран терминала: экран меняется — агент работает, не меняется дольше 2,5 секунды — ждёт
(`internal/live`). Код выхода агента берётся у tmux. Реестр Grok знает только, что процесс жив:
по нему «Нить» видит, что сессия идёт в другом терминале, а в своём терминале смотрит на экран.

## Запросы

Всё под `/api`, ответы в JSON, время — секунды Unix. Изменяющие запросы — POST с проверкой Origin.
Типы — в `internal/server/api.go`, их копия на TypeScript — в `web/src/api/types.ts`.

С телефона те же запросы идут через встроенный узел Tailscale (`internal/remote`): вход по ссылке
с ключом даёт телефону свой ключ устройства в cookie, Host должен быть адресом узла, а POST
и WebSocket — с Origin этого адреса. Запросы `/api/remote*` с телефона запрещены.

| Запрос | Что возвращает или делает |
|---|---|
| `GET /api/health` | жив ли сервер; телефон по нему узнаёт, что его отключили |
| `GET /api/bootstrap` | агенты, окружение (tmux, WSL, VS Code), настройки, проекты, сессии без служебных |
| `GET /api/events` | поток событий (SSE), см. ниже |
| `GET /api/sessions?project=&agent=&service=1&limit=&cursor=` | история с фильтрами, по дням; `before=` тоже работает |
| `GET /api/sessions/{key}` | сведения: переписка (до 60 сообщений), сводка, команда продолжения, команда подключения, запуск |
| `POST /api/sessions/{key}/{rename,pin,hide,done,seen}` | пометки человека |
| `POST /api/sessions/{key}/resume` | открыть сессию в терминале |
| `GET /api/sessions/{key}/finish` | что помешает удалить копию: незакоммиченные файлы, неотправленная ветка, другие агенты в копии |
| `POST /api/sessions/{key}/finish` | остановить агента, закрыть терминал, отметить, по желанию удалить копию |
| `POST /api/sessions/{key}/summary` | составить сводку по сессии; `agent` выбирает, кто пишет; ход — в событиях `job` |
| `GET /api/jobs`, `POST /api/jobs/{id}/cancel` | идущие сводки и их отмена |
| `POST /api/project` | закрепить или скрыть проект, задать агента по умолчанию |
| `GET /api/models?agent=` | модели и уровни рассуждений агента для окна запуска |
| `GET /api/launch/check?path=&prompt=` | git ли это, кто уже работает в папке, предложенная ветка |
| `POST /api/launch` | проект, агент, модель, рассуждения, папка или копия, ветка, запрос → ключ новой сессии |
| `GET /api/terminal/{key}?cols=&rows=` (WebSocket) | терминал; `?view=full` подключается, не меняя размер окна агента |
| `GET /api/terminal/{key}/screen?history=` | экран текстом для телефона, с `history` строками истории |
| `POST /api/terminal/{key}/keys` | текст или клавиши для телефона |
| `GET /api/search?q=&conv=1&service=1` | быстрый поиск: до 200 находок, запрос до 500 символов |
| `POST /api/search/full` | полный поиск по журналам, ход — в событиях `search` |
| `GET /api/digest?days=3\|5\|7` и `POST /api/digest` | сводка за несколько дней (не больше 200 сессий); готовая — в событии `digest` |
| `GET /api/remote`, `POST /api/remote`, `POST /api/remote/key`, `POST /api/remote/devices/{id}/revoke`, `GET /api/remote/qr.svg` | доступ с телефона; только с компьютера |
| `GET /api/reboot` и `POST /api/reboot` | сессии, открытые до перезагрузки, и их продолжение |
| `GET /api/settings` и `POST /api/settings` | настройки |
| `GET /api/env` | проверка tmux и агентов для первого запуска |
| `POST /api/reveal` | открыть папку или VS Code |
| `GET /api/export` и `POST /api/import` | данные одним файлом |

`GET /api/sessions` отдаёт в заголовках `X-Total-Count` (сколько сессий подходит под фильтры без учёта
страниц) и `X-Next-Cursor` (значение `cursor` для следующей страницы; пусто — страниц больше нет).

События потока `GET /api/events`:

| Событие | Что приходит |
|---|---|
| `sessions` | изменившиеся сессии, вместе с состоянием их терминалов |
| `projects` | список проектов целиком |
| `progress` | ход чтения журналов при запуске |
| `notice` | сообщение для всплывающего окна, например агент не запустился |
| `search` | ход и находки полного поиска |
| `job` | ход сводки по сессии или за несколько дней |
| `digest` | готовая сводка за несколько дней |
| `remote` | состояние доступа с телефона; только на компьютер |
